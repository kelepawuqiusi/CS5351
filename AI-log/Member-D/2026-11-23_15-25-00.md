## Reading the delta

- **Input is the moving part.** Input rose 8.3% on the three-run average while output was roughly flat (-0.6%) and latency stayed flat (+0.2%). The new code injects more per-call context: resolved instrument identity context, portfolio context, expanded grounding prose in system prompts, and structured-output tool schemas on bound calls. Candidate causes to verify with B/C: the `agents/context.py` expansion, trader/researcher/risk prompt prose, and schema binding.
- **Input variance is wide.** A3's input (115.8k) sits near the old baseline, while A1/A2 are ~130k; the average hides this spread. Per-node attribution (separate record) shows the analyst tool loop and the risk/research stages as the main input consumers.
- **Call count** is 0.8 higher on average, consistent with one extra structured turn in the later stages.
- **Decision variance persists.** With fixed configuration the after-build trio produced `Hold`, `Overweight`, `Hold`; the baseline pair was `Overweight` both times. Record as reproducibility variance, not as a model or prompt change.

## Gaps rechecked against this build

1. **Run status.** `runapi/result.py` now defines `RunOutcome` (`COMPLETED`/`INCOMPLETE`), `stop_reason`, `output_check`, and findings at the API boundary. The legacy propagate/CLI report header (`reporting.py:_header`) still writes only Analysis date, Rating, Generated — **no status field in the saved report**. The RUN-001 boundary model exists; surfacing it in the report is still missing.
2. **Action field.** The trader prompt still asks for `Action: Buy / Hold / Sell` inside prose; the header still has no separate Action label. The FR-006 gap persists at the report level.
3. **Missing-data disclosure.** `dataflows/date_window.py` now emits an explicit "`<source> unavailable for range: reason`, so this is not an absence" sentinel at the data layer. StockTwits 403 and Reddit 404 still degrade silently in the run log; report-level disclosure was not verified on a saved after-build report, because the propagate measurement path writes no report folder.

## Anomalies

- **Two stalled late-stage calls.** The first attempt hung at `trader_node`; the second at `conservative_debator`. The main thread was blocked in httpx reading response headers: elapsed >10 min, ~0 CPU time, no timeout raised. Isolated gateway probes — plain completion, tools array, forced tool choice, and a bound structured-output call — all answered in under 2 s. The LLM factory sets no read timeout, so the SDK's long default lets a stalled call block indefinitely. Hand-off to B/A: reproduce with a short timeout and inspect late-stage request size and context.
- **Partial stats before the second stall:** 15 calls, 79,699 in, 16,849 out at 70 s. Excluded from the average; treated as INCOMPLETE per NFR-001.
- **Vendor noise:** StockTwits HTTP 403; Reddit RSS HTTP 404; FRED macro channel unavailable (key unset), retried per lookup.
- **Network note:** these runs were taken on a different network path to the CityU WAF than the baseline (Hong Kong to Singapore). The two stalls may reflect path or gateway instability rather than code. Keep the per-call timeout guard for future runs so a stall fails fast instead of blocking for minutes.
