**Summary (English):** Member A asked D to assess whether five proposed cost/time requirements are achievable on the current boundary, before priorities are fixed. Inspected build `main @ 98b82c9` (PR #9 after it is CI/docs/test only, no runtime change). This is feasibility input from D; A owns final priority and wording. No implementation is claimed and no fit test is written here (that is C's).

**Source question:** `confirm-to-D-2026-11-23.md` (A, 23 Nov 2026), requirements `NFR-COST-001/002/003`, `NFR-PERF-001/002`.

## Evidence pointers in the inspected build

- Retry passthrough: `llm_clients/openai_client.py:213`, `anthropic_client.py:10`, `google_client.py:52`, `azure_client.py:9`, `bedrock_client.py:69`; factory forwards `max_retries` only when explicitly set (`llm_clients/factory.py:121-125`).

- Structured-output fallback: `agents/structured.py:96-98` re-raises `ContextBudgetError` before the generic `except Exception`; the generic branch returns `None` and retries free text.
- Memory settlement catch-alls: `memory/settlement.py:159` and `:173` wrap reflection and log update in bare `except Exception`.
- ChatGPT-plan auth renewal throttle: `llm_clients/chatgpt_auth.py:217-240` (`_retry_after`), an auth-layer retry outside LLM retry config. The plan client refuses only `temperature`, `top_p`, `max_tokens` (`openai_client.py:170`).
- Debate state is free-text: `agents/state.py` `bull_history`, `bear_history`, end-of-run `final_rating`; no structured per-round stance field.
- Timing evidence: after-build completed runs 111.8–117.0 s; two earlier attempts stalled >10 min blocked in httpx response headers with no SDK read timeout (see `2026-11-23_15-25-00.md` Anomalies).

## Reply to A (D1–D9)

```text
D1: Retry disable is reachable on the wrapped families — OpenAI-compatible
(deepseek, minimax, openrouter, xai, qwen, glm, groq, nvidia, ollama/local,
openai-compatible), Azure, Anthropic, Google, Bedrock — via max_retries=0 in
the shared passthrough. Not provable on every client today:
  (a) the factory forwards max_retries only when explicitly configured; unset
      keeps the SDK default (usually 2);
  (b) internal SDK retries are invisible to graph callbacks; attempt counting
      needs a run-level dispatch wrapper, and no such controller exists in
      runapi/ yet;
  (c) the ChatGPT-plan path renews its sign-in token under a separate auth
      throttle (chatgpt_auth _retry_after) that max_retries does not govern;
  (d) local/keyless endpoints may not honor retry semantics uniformly.
Verdict: enforcement is achievable on the OpenAI-compat/native families once a
dispatch wrapper exists; not on the plan path until auth renewal routes through
the controller.

D2: Yes, offline-testable with the current decoupling. EventSink is an
in-memory list; persistence (publish_run) is a separate single-commit final
stage. Build the reservation/controller behind that boundary, inject a
threading Barrier/Event around the reservation call, drive 4 workers contending
for the last slot, and assert reservation counts and refusals against the
in-memory sink without calling publish_run. Alternative: mock the persist
layer and assert sink event order. Assumes controller and sink stay decoupled
(currently they are); the reservation component does not exist yet.

D3: Yes, but only with a dedicated exception type caught before the generic
handlers. Precedent exists: ContextBudgetError is re-raised ahead of except
Exception in structured.py, so it survives the structured fallback. Today
settlement.py wraps reflection and log update in bare except Exception; a
plain refusal there would be swallowed as "reflection failed" and look
identical to an ordinary failure. Define a CallBudgetError (budget-refusal
hierarchy), catch/re-raise it first in both the structured fallback and
settlement handlers, and tag a distinct sink outcome (e.g. BUDGET_REFUSED).

D4: Agree with downgrade, but split finer than plain detection-only:
  (a) Detection tier (Should, all clients): count dispatches and reservations,
      record over-cap as a finding; no hard guarantee.
  (b) Enforcement tier (Must, restricted subset): fresh single-use reservation
      per attempt, SDK retries disabled, controller wraps every dispatch;
      claim it only for clients verified to honor max_retries=0 with no hidden
      auth retry.
Keep B's reservation model; its enforcement scope is the verified subset.

D5: Partially observable. The measured CityU deepseek-compatible path returned
usage_metadata on every completed run. Genuinely unknown-risk paths:
local/keyless OpenAI-compatible servers and gateways that omit the usage
object; streaming responses without usage return; wrappers that drop
usage_metadata. The handler falls back to llm_output.token_usage, then leaves
0 if absent — it cannot distinguish "zero tokens" from "unknown". Restate:
require an explicit usage-present/absent flag per call; absent usage is an
UNKNOWN failure (not zero), and the provider/model path is named in the finding.

D6: Partly workable. Only if budget refusals are separated from
infra/timeout incompletes. With a time cap near the natural run duration
(~114 s measured, range 111.8–117.0 s), marginal runs flip COMPLETED/
INCOMPLETE between repeats, making the 20-run pass/fail unstable. Split
INCOMPLETE(BUDGET_REFUSED) (deliberate cap hit; evidence the controller
worked) from INCOMPLETE(TIMEOUT/INFRA). The criterion counts infra failures;
budget refusals are reported as cap evidence, and the cap sits above measured
natural duration with margin. Note: 20 sequential runs x ~115 s ≈ 38 min per
criterion pass.

D7: No, a cooperative between-step check is not enough. It acts only before
dispatching a call; it cannot abort one already in flight. Evidence: two
stalls blocked >10 min in httpx response headers with no SDK read timeout; a
single in-flight call can far exceed 2 s, and measured turns span seconds.
Meeting a tight allowance needs a per-call abort/timeout, bounded cleanup, and
a terminal path that does not wait on settlement/persistence. Alternative:
keep cooperative deadline checks between steps but size the allowance for one
in-flight call plus cleanup; or define the deadline at step boundaries and
exclude final terminal/settlement IO from the allowance.

D8: Not deterministically on the current state. State carries free-text
bull_history/bear_history and one end-of-run final_rating; there is no
structured per-round stance (rating/action enum) to compare between rounds.
Deterministic convergence needs a structured per-round stance field plus a
stable-equality check. Without that, "converged" is a model judgment, which
is not an acceptable fit criterion. COST-003 cannot be fit-tested
deterministically as written; either extend state with a structured stance,
or descope.

D9: Recommended cuts, in order:
  1. Drop/descope NFR-COST-003 (early convergence): no deterministic signal
     today; model judgment unacceptable; lowest return for the effort.
  2. Relax NFR-PERF-002's 2 s terminal allowance rather than build to it; keep
     the deadline concept with a realistic allowance and per-call abort.
  Keep: COST-001 (usage observation with explicit UNKNOWN flag, measurable
  today), COST-002 detection-only tier, PERF-001 repeated-run runtime cap
  (measurable against the ~114 s baseline).
```
